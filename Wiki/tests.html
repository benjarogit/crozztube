🧪 Tests & Harness

Das Harness prüft den laufenden Docker-Stack von außen (HTTP, DB, Queue, Browser) und ist so gebaut, dass ein Agent es ohne manuelle Schritte komplett ausführen kann. Letzter vollständiger Lauf: 102 Harness-Checks + 9 Browser-Tests grün.

Ausführen

cd "/mnt/intern-1tb/Projekte - Vibe Coding/crozztube"

./tools/test/run.sh               # alle Suiten
./tools/test/run.sh list          # Suiten auflisten
./tools/test/run.sh stack api     # gezielt
./tools/test/run.sh all           # explizit alles

SLOW=0 ./tools/test/run.sh jobs refresh   # yt-dlp-Roundtrips überspringen
UI_SKIP=1 ./tools/test/run.sh all         # ohne Browser
KEEP_TEST_VIDEOS=1 ./tools/test/run.sh api  # Test-Importe nicht löschen
CRZZ_VERBOSE=1 ./tools/test/run.sh ui     # Fehler-Log ausgeben

Suiten

refreshStatus-Metadaten, hängende refreshing-Zustände, erzwungener Refresh bei frischer Quelle, simulierter Ablauf + automatische Erneuerung, 5 parallele Requests → genau ein Resolve
mirrorProvider-Matrix (YouTube/Short/Vimeo/Dailymotion/Twitch/Direct), Embed-URLs, mode, Slug-Lookup, 404 bei unbekanntem Slug
jobsCommands registriert, Scheduler-Einträge, Probe erkennt gute/defekte URLs, refresh-expiring wählt Ablaufkandidaten und arbeitet die maintenance-Queue ab
thumbnails80 PHP-Integrationsprüfungen und fünf HTTP-Vertragsprüfungen; kein externer Testupload.
uiPlaywright: Mirror-Toggle + Overlay, Reload-Persistenz, SPA-Navigation, Auto-Refresh mit Banner/Reload, Fehlerbanner mit Retry + Mirror; Bild-Fallback ohne Backend-Anfrage, Platzhalter, HLS-Shorts/Seek und Kapitel/Kapitelsprung (9 Tests).

Thumbnail-Prüfungen

./tools/test/run.sh thumbnails führt 80 PHP-Integrationsprüfungen in einer zurückgerollten Datenbanktransaktion aus: Provider-Fallback, Deduplizierung, RAM-/Größen-/SSRF-Grenzen, manuelle Bilder, sichere Migration, Nachtbudget und Stopp um 05:00, Short-Regel und Fehlerklassifikation. Hoster-Antworten sind simuliert; Live-Uploads brauchen lokale Keys. Dazu kommen fünf HTTP-Prüfungen für Zugriff, Raw-Body, Dateiupload-Sperre und Größenlimit.

Playwright

cd tools/test/ui
npm install
npx playwright install chromium
npx playwright test
npx playwright test specs/refresh.spec.ts --headed

Die Browser-Tests loggen sich per API-Token ein (localStorage['playhub_token']) und manipulieren für Ablauf-/Fehlerfälle die Tabelle crozztube_import_sources per docker exec. Die Originalzeile wird in afterAll wiederhergestellt; vorher wartet der Test, bis Queue und refreshing-State leer sind.

Wie das Harness den Stack schützt

  • Setzt zu Beginn storage/framework/crozztube-maintenance.pause, damit der 5-Minuten-Scheduler nicht mit den Tests konkurriert; entfernt die Datei beim Beenden.
  • Registriert selbst angelegte Test-Videos und löscht sie im EXIT-Trap (außer KEEP_TEST_VIDEOS=1).
  • Stellt manipulierte Zeilen (Ablauf, Fehlerzustand) nach dem Lauf wieder her.
  • Prüft Zeitfenster über feste Werte ('2000-01-01 00:00:00') statt SQL-NOW() — die MySQL-Session läuft in UTC, die App in Europe/Berlin.

Bekannte Stolpersteine

SymptomUrsache / Lösung
Too Many Attempts auf /statusThrottle-Präfixe pro Route prüfen; Segment-Traffic darf den Status-Bucket nicht teilen.
