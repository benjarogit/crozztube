5. yt-dlp Source-Resolver (Plugin) FERTIG · v0.7.1

Implementiert:
A) Direkt-URL via yt-dlp = Pflicht. Beim Import (POST /api/video-imports) wird der Job ResolveImportSource dispatcht (auch für direct). yt-dlp (-J, keyless) liefert Metadaten + Direkt-URL. Auswahl: HLS-Manifest bevorzugt → sonst progressive MP4. Bei einer direkt verlinkten Datei meldet yt-dlp keine Codecs/Höhe — solche vollständigen Dateien (mp4/webm/m4v/mov) werden trotzdem als progressive Quelle übernommen, die Dauer wird per ffprobe nachgelesen; die MP4 bleibt beim Original-Host.
A2) yt-dlp als Metadaten-Engine (v0.6.0). Der Provider direct („Video URL (direct or yt-dlp)“) akzeptiert jede von yt-dlp verstandene URL. App\Support\YtDlp liest Titel, Beschreibung, Tags, Thumbnail, Dauer, Kapitel und Autor (10-min-Cache); Provider-APIs/HTML-Metadaten haben Vorrang, yt-dlp füllt Lücken. Dadurch funktionieren auch Seiten ohne eigenen PlayHub-Provider (TikTok, X, Reddit, SoundCloud …) als Streaming-Import. GET /api/source-resolver/health zeigt yt-dlp-/ffprobe-Version und Quellenzahlen.
YouTube-Sonderfall (SABR/DASH): YouTube liefert kein muxed MP4 mehr und kein Master-Manifest. Das Plugin baut deshalb ein synthetisches HLS-Master-Manifest (/api/source-resolver/manifest/{id}): es verbindet die separaten Video-Playlists (144p–2160p, AVC/VP9) mit der AAC-Audio-Playlist (itag 233/234) zu einer gültigen Master-Playlist. Segmente streamen per Passthrough-Proxy (/api/source-resolver/playlist + /seg, googlevideo-Allowlist) direkt vom Original-CDN — nichts wird gespeichert oder re-gehostet, der Proxy existiert nur, weil googlevideo kein CORS sendet.

Endpoint (Plugin-Routen)Zweck
GET /api/source-resolver/status/slug/{slug}State für die Watch-Page in einem Request (kein zusätzlicher Video-Call)
GET /api/source-resolver/status/{videoId}Gleicher Payload per ID (Harness/Backoffice)
POST /api/source-resolver/refresh/{videoId}Refresh anstoßen (idempotent, Single-Flight; force umgeht den Debounce)
GET /api/source-resolver/manifest/{videoId}Synthetisches HLS-Master-Manifest; stößt bei abgelaufener Quelle im Hintergrund einen Refresh an
GET /api/source-resolver/playlist?url=…&video_id=…CDN-Playlist-Passthrough + Segment-URL-Rewrite; CDN-Fehler → Refresh
GET /api/source-resolver/seg?url=…CDN-Segment-Streampassthrough (nur *.googlevideo.com)
GET /api/source-resolver/download/{videoId}Passthrough beste MP4; 409 bei HLS-only. Kein UI-Button (bewusste Entscheidung), Endpoint bleibt für Admin/Skripte
Status-Payload (Auszug): state, fresh, has_direct, refreshing, expires_at, expires_in, can_refresh, retry_after, error_message, mirror (provider, label, mode: iframe|link, embed_url, external_url).

B) Ablauf-Refresh: TTL wird aus den expire=-Parametern der gespeicherten CDN-URLs berechnet (YouTube ~6 h). Ablauf → State stale → Watch-Seite bzw. RefreshSource erneuert; Single-Flight-Lock (Cache-Lock 600 s) verhindert parallele Doppel-Refreshes. Zusätzlich koalesziert der Job nach Anforderungszeitpunkt: Erneuert ein Job die Quelle, steigen alle älteren, bereits eingereihten Anfragen aus — auch mehrere Nutzer lösen so nur einen yt-dlp-Lauf aus. Eine hängende refreshing-Zeile blockiert die UI nicht (nach 9 Min. wird sie ignoriert).
Frontend-Flow: Banner „Quelle wird erneuert…“ → Polling → bei frischer URL automatischer Reload (max. 2 Versuche, Resume-Position) → bei hartem Fehler Banner mit Retry + Mirror. Ohne JavaScript greifen die Manifest-/Playlist-Sicherheitsnetze serverseitig.

C) Provider-neutraler Mirror: Mirror::forVideo() entscheidet serverseitig über iframe (YouTube/Vimeo/Dailymotion/Twitch) oder link (direkte Datei-URL). Der Button unter dem Video und das Overlay im Player sind provider-unabhängig; die Auswahl wird pro Video im Browser gespeichert. embed_url im VideoResource bleibt für YouTube leer, damit die Direktquelle Priorität behält.

D) Wartungs-Jobs: refresh-expiring erneuert Quellen 15 Min. vor Ablauf in kleinen, gestaffelten Batches (Queue maintenance). probe prüft nachts gespeicherte URLs per HEAD (Fallback: Range-GET), protokolliert last_checked_at/last_check_status und erneuert defekte Quellen. Beide respektieren die Pause-Datei.

Betriebshinweise & Zeitfalle: yt-dlp ist im Image (2026.10.26) und wird vom cron-Container täglich aktualisiert (Marker /tmp/.crz-yt-dlp-last-update). Nach Plugin-Updates: php artisan queue:restart (Worker lädt Job-Klassen sonst nicht). DB-Tabelle: crozztube_import_sources. App-Timezone ist Europe/Berlin, die MySQL-Session läuft in UTC → in Plugin-Code und SQL-Vergleichen kein NOW() verwenden; Zeitstempel aus PHP formatieren. Jede Plugin-Route hat ein eigenes Throttle-Präfix, damit Segment-Traffic den Status-Endpoint nicht blockiert.
