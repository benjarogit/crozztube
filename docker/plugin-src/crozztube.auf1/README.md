# AUF1 provider

Recorded AUF1 video pages are detected through the normal import-provider registry, including batch imports. Title, full description, published tags, thumbnail, duration and available chapter boundaries come from the same **undocumented** `https://auf1.tv/api/getContent/{public_id}` endpoint used by the official website. Schema and content identity are checked; empty HTTP-200 responses, live content, radio, `/eilt/` posts and non-video URLs are rejected. API availability is not guaranteed. No native AUF1 yt-dlp extractor is assumed.

The numeric content `id` is the provider identity (`external:auf1:6428`). Neither a page slug, `videoData.id` nor a PeerTube/Bunny hosting UUID replaces it. A manual Direct selection for an AUF1 page uses the verified AUF1 record too, preserving duplicate protection and the official Mirror.

Source Resolver 0.9.0 discovers at most three validated media candidates: the published Gegenstimme/PeerTube master, Bunny master and one video MP4 fallback. yt-dlp extracts the chosen media URL, not the unsupported AUF1 watch page. Segments remain at the original host; no video is stored. Audio-only downloads are excluded. Only explicit resolution-labelled MP4 entries qualify. Fresh native playback is preferred; the official published PeerTube/Bunny iframe stays available through **Mirror**. If metadata cannot be refreshed, Mirror retains the original AUF1 page link.

URL and API handling rejects credentials, custom ports, foreign redirects, arbitrary CDN hosts and unrelated hosting IDs. Supported media hosts are deliberately narrow (`gegenstimme.tv`, the currently verified `vz-0b49e78d-475.b-cdn.net`); Bunny embeds must use AUF1 library `171363`. A provider/CDN schema change requires review rather than silent expansion of the allowlist. Responses have a 2 MiB transfer limit: oversized Content-Length is rejected before the body and a progress callback aborts chunked or misleading-length transfers as they cross the limit. Compression is neither requested nor decoded, avoiding unbounded decompression. A final body-length check remains as a defense for alternative/fake transports. Requests also have a 5-second connect/12-second overall timeout and ten-minute cache. Native retries refresh through the normal resolver queue. A changed content identity during refresh is rejected.

Captions, multilingual audio and original-language markers are **not guaranteed**. The tested records expose no captions, while one has 14 real chapters. Existing extractor evidence, if any, is retained without inventing language labels or chapters. Live streams and AUF1 Radio are outside this provider.

Build `bash tools/dev/package-plugin.sh crozztube.auf1`. Upgrade Source Resolver first, preserving settings and temporarily disabling enabled dependent provider plugins through normal plugin management; restore those plugins afterwards, then install/enable AUF1. Core support for source-context embeds is also required. A long-running Laravel worker needs a graceful `queue:restart` after deployment, never an interrupted job.

Fixture checks: `docker exec crozztube-web php tools/test/php/auf1-provider-checks.php` and `node --test tools/test/import-providers.test.mjs`.

Optional upstream metadata smoke: `docker exec crozztube-web php tools/test/php/auf1-live-smoke.php metadata`. The three samples are [news with chapters](https://auf1.tv/nachrichten-auf1/nachrichten-auf1-vom-06-november-2026/), [long-form discussion](https://auf1.tv/auf1-am-abend/die-grosse-verarsche-wir-haben-es-so-satt-aaa-5-11-26/) and [shorter interview](https://auf1.tv/nachrichten-auf1/risiko-ki-was-ich-nicht-aendern-kann-muss-ich-verwenden/).

Optional queued resolution smoke (creates a transient diagnostic job/cache result, no videos): run `auf1-live-smoke.php dispatch auf1-smoke`, then `php artisan queue:work --once --queue=auf1-smoke --tries=1 --timeout=180`, then `auf1-live-smoke.php result TOKEN`. Use `dispatch maintenance` after a graceful deployment to verify the regular worker instead; do not run a second worker on the normal queue just for this check. Reading a result removes it; unread results expire after ten minutes.

Evidence, checked 6 November 2026: [official API example](https://auf1.tv/api/getContent/nachrichten-auf1-vom-06-november-2026), [official client API/embed implementation](https://auf1.tv/_nuxt/D-3tEDbH.js), [yt-dlp supported extractors](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md). yt-dlp 2026.06.09 rejected the AUF1 page and successfully extracted its published master HLS.

Source Resolver **0.9.1** keeps a validated published HLS master intact when every video rendition already contains audio and there is no separate language/original-audio selection to preserve. Such AUF1 streams must not enter the Googlevideo-only split-stream proxy: their relative init/segment paths and byte ranges are served by their original host. Split video/audio and multiple language tracks retain the existing selection logic.

Playback acceptance must include actual media, not just `fresh` resolver status. For an existing public import, run `docker exec crozztube-web php tools/test/php/auf1-live-smoke.php media VIDEO_ID` for bounded A/V decoding. Run `node tools/test/ui/auf1-native-playback.mjs VIDEO_SLUG` for a short real Chromium playback check with decoded video frames/audio, no Mirror and read-only API responses. It allows only the published Gegenstimme stream and the player's Hls.js dependency through the test's normal external-request block; media requests are bounded and the context is closed afterwards.
